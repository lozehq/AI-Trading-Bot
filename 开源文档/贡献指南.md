# 贡献指南

感谢你愿意为本项目贡献！请先快速浏览本指南，保持一致的协作流程与代码质量。

## 如何开始
1. Fork 本仓库，并创建你的工作分支：
   - 功能：`feature/简要描述`
   - 修复：`fix/简要描述`
   - 文档：`docs/简要描述`
2. 本地克隆并安装依赖：
   ```bash
   npm install
   cd client && npm install && cd ..
   ```
3. 复制环境变量并按需设置（建议先使用 demo/paper 模式）：
   ```bash
   cp env.example .env
   ```

## 开发与调试
- 启动开发模式：
  ```bash
  npm run dev
  ```
- 健康检查：`GET /health`
- 前端：`http://localhost:5173`  
  后端：`http://localhost:3000`

## 提交规范（建议）
- 提交信息使用简洁、清晰的动词开头：
  - `feat: 新增 OKX 账户余额接口`
  - `fix: 修复 AI 分析超时处理`
  - `docs: 更新 使用说明`
  - `chore: 调整日志级别`
- 单个 PR 聚焦一个主题，尽量小而完整。

## 代码风格与质量
- 保持一致的命名与模块化拆分。
- 禁止在代码中硬编码凭证；使用 `.env` 或后端加密存储。
- 日志与错误处理：避免输出敏感信息（凭证、Token、Passphrase 等）。
- 接口参数校验：后端路由务必使用校验（如 Joi）。

## 测试与自检
- 变更后至少验证：
  - `GET /health` 状态为 200
  - 关键页面可正常加载
  - 涉及交易功能的改动请在 `demo/paper` 模式下自测通过
- 如改动影响配置/用法，请同步更新 `docs/使用说明.md` 或相关文档。

## 提交 PR
1. 在 PR 描述中写明：变更目的、关键改动、验证方式、是否影响配置。
2. 关联相关 Issue（如有）。
3. 通过 Code Review 后合并；如有冲突请先在本地解决再提交。

## 行为共识
参与社区需遵守《行为准则》。若发现不当行为，请在 Issue 中联系维护者并说明情况（无需公开个人隐私）。

## 安全与披露
如发现安全问题，请遵循《安全政策》的私密披露流程。切勿在公开渠道直接贴出漏洞细节或敏感数据。

再次感谢你的贡献！🙏
